# Let repositories add their own rules to `CODESTYLE.md`

> Issue: [#41](https://github.com/chA0s-Chris/repo-baseline/issues/41)

## Rationale

`CODESTYLE.md` is a synced whole file of the `dotnet` profile, so a repository cannot add rules to it: `check` reports every local edit and `sync` overwrites it. Repositories with code-style rules that cannot be shared put them into `AGENTS.md`, and a reader of `CODESTYLE.md` misses them. `.editorconfig` already has a shared block followed by local settings; the file that describes the code style should follow the same pattern.

The goal is that `CODESTYLE.md` holds the shared rules in a managed block and the repository's own rules below it, and that existing repositories move to this shape in the `sync` that applies the new profile release, without duplicated rules.

## Acceptance Criteria

- [x] After `sync` with the new profiles, `CODESTYLE.md` has the shared block `code-style` at the start; a file that is not a former synced file keeps its local content; `check` compares only the block.
- [x] `init` creates `CODESTYLE.md` from a new template: the block, then an empty local section `### Repository-Specific Rules` with one sentence on what belongs there.
- [x] A block target for which a selected profile defines a block, that has no block markers and whose first line is the `repo-baseline` whole-file header, is a former synced file. `sync` replaces it completely with its blocks and lists it as replaced; afterwards the file consists only of its blocks, as for a new file, and `check` reports no finding for the file.
- [x] `check` reports a former synced file with its own finding that says to run `sync`, instead of reporting its blocks as missing. A block target that no selected profile defines a block for gets no such finding.
- [x] A block target without that header on its first line still gets its missing blocks inserted at their positions, as before.
- [x] With `--force`, `init` replaces a former synced file that has no template in the same way instead of merging blocks into it, and lists it as replaced; without `--force` it still skips the file.
- [x] The documentation sends repository-specific code-style rules to the local section of `CODESTYLE.md`: `docs/design.md` describes `CODESTYLE.md` as a block target and the rule for local rules, and its list of block uses names `CODESTYLE.md`; the `CODESTYLE.md` entries of `docs/layout-dotnet.md`, in the tree and the table, mark it as a block file, and the table row sends these rules to its local section instead of `AGENTS.md`; `docs/decisions.md` has a new entry CS-15; the `code-style-and-inspections` block of `AGENTS.md` sends these rules to the local section of `CODESTYLE.md`.
- [x] The documentation describes the migration: `docs/design.md` describes the replacement of former synced files and tells a migrated repository to add `### Repository-Specific Rules` below the block and to move its code-style rules there from `AGENTS.md`; the `sync` and `check` rows of the Tool table in `docs/design.md` and of `README.md` mention the replacement and the new finding; the update section of `README.md` says that a profile release can need a newer tool, and that the tool update in `dotnet-tools.json` is merged before the profile update.
- [x] `tool/minimum-tool-version` holds `0.2.0`.
- [x] Unit tests cover the detection of a former synced file: a BOM, CRLF line endings, trailing whitespace, a header on a later line, a first line that only starts like the header, a header together with block markers, and the Markdown and `#` syntax. Tool tests use fixture refs in which a Markdown whole file becomes a block target (for `init`, an `init_fixture_ref` in which a file without a template, such as `CLAUDE.md`, becomes one), and cover the replacement by `sync` and by `init --force`, the `check` finding, a repeated `sync` that keeps an added local rule, the unchanged behavior for block targets without the header, a former synced file whose block no selected profile defines, which `sync` leaves unchanged and `check` does not report, a former synced file with block markers hidden by an unclosed fence, which still stops `sync`, and a former synced file whose unclosed fence would only precede an inserted end-position block, which is replaced.
- [x] The real-profiles tool test checks that `init` writes `CODESTYLE.md` with the filled `code-style` block followed by `### Repository-Specific Rules` outside the markers, and that `sync` lists a former synced `CODESTYLE.md` (the header, an empty line, then the fragment's content) as replaced, leaves only the block, and `check` passes.

## Technical Details

**Profile content.** The shared content moves from `profiles/dotnet/files/CODESTYLE.md` to a new fragment `profiles/dotnet/blocks/codestyle.md`, without the header line and the empty line after it, so the block starts with `## Code Style Guidelines`; blocks carry no header. `profiles/dotnet/profile.json` gets the block `code-style` for `CODESTYLE.md` at position `start`. `## Code Style Guidelines` stays inside the block, so the local section is a third-level heading under it. The new template `profiles/dotnet/templates/CODESTYLE.md` contains the block markers and the local section.

**Local rules.** They add rules, or override a shared rule and name the rule they replace, so that the file never contains two rules that silently contradict each other. Rules that apply only to one subtree may stay in a nested `AGENTS.md` there. CS-15 records this with the status Confirmed, and `docs/design.md` states it next to the rule "One source per rule".

**Detection.** A former synced file has no block markers, and its first line, without trailing whitespace, is the complete whole-file header `Managed by repo-baseline (<url>). Do not edit; change it there.` between `<prefix>` and `<suffix>` of the file's `MarkerSyntax`, where `<url>` is any non-empty text without whitespace or parentheses. Detection runs on the text that `TextFile.TryDecode` returns; the BOM and CRLF cases are tested through that decoding. Matching the complete sentence keeps a hand-written comment that merely starts the same way from triggering a destructive replacement; the variable URL keeps the rule independent of where `repo-baseline` is hosted. The new fixture refs use the complete header; the existing fixtures stay unchanged, and the short header `<!-- Managed by repo-baseline. -->` serves as the case that is not detected. Only `*.md`, `.editorconfig` and `.gitignore` can be block targets (`MarkerSyntax.ForFile`), so a shebang line before the header cannot occur. A header on any later line is local content.

**Replacement.** `sync`, and `init --force` for a block target without a template, treat a former synced file as empty text before `BlockMerger.Apply`, so the file then consists of its blocks only; with a template, `init --force` writes the template as before. `sync` never reads templates, and a migrated repository adds the local section itself when it needs one. Edits in the former synced file are lost; they were never allowed, Git history keeps committed ones, and uncommitted ones are overwritten. The existing handling of case variants, malformed markers, markers hidden by an unclosed fence and invalid UTF-8 stays in front of the replacement and runs on the existing file, so such a file still stops `sync`; only the condition for inserting an end-position block after an unclosed fence runs on the text that is actually merged, because the dropped content cannot hide a block. `check` detects a former synced file before evaluating that fence condition, so such a file gets only the finding to run `sync`. The rule applies to every block target, not only `CODESTYLE.md`. A former synced file is replaced only when a selected profile defines a block for it; otherwise it stays as it is, as today.

**Compatibility.** A tool older than `0.2.0` would insert the block above the old file and duplicate every rule, so the new profiles require `0.2.0`. After the merge, tool `0.2.0` is released first; the profile release preflight refuses to run until nuget.org lists it. The minimum applies to release archives only; with `--checkout` or `--ref`, a migration needs tool `0.2.0` or a development build that contains it. Syncing an older profile release overwrites `CODESTYLE.md` as a whole file and drops its local rules; `docs/design.md` says so. The pull request title names the move, such as "Move repository-specific code-style rules into `CODESTYLE.md`", so release-drafter puts the hint into the published profile release notes without a manual edit.
